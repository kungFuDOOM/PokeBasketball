# Username word list

The username filter (client `src/multiplayer/ranked/username.ts`, server `pokejam_name_check` in
`supabase/migrations/20261114_pokejam_profiles.sql`) uses the English dataset of **obscenity** 0.4.6
(https://github.com/jo3-l/obscenity), MIT licence, copyright 2025 Joseph Liu. Its words come from **cuss**
(https://github.com/words/cuss), MIT, copyright 2016 Titus Wormer. The licence text is in `third-party/obscenity-LICENSE.md`.

- `src/multiplayer/ranked/nameFilterData.json` is generated by `scripts/import-name-wordlist.mjs` (run against an unpacked
  `npm pack obscenity` tarball). It flattens the dataset into plain terms: **severe** (slurs and the worst words, blocked anywhere
  in a name) and **mild** (short or ambiguous words, blocked only as a whole name or a whole `_` segment), plus the dataset's own
  whitelist and extra allowlist words (the Scunthorpe problem). Reserved names and staff-impersonation terms are kept in the same
  script. The file is never shown in the UI.
- `scripts/gen-name-filter-sql.mjs` writes the migration's seed block from that JSON. `supabase/tests/usernames.test.ts` fails
  if the migration, the JSON and the client lists differ, and checks that client and server give the same verdict on a corpus.
- To change the lists: edit the constants in the import script (or re-import), run both scripts, run the tests. A new migration
  is needed to change an already applied database (the seed block deletes and reinserts the whole blocklist, so re-running the
  generated block is safe).
- Not a complete filter. Look-alike letters beyond the mapped digits, other languages and creative spellings can get through;
  moderators can rename a player with `pokejam_admin_force_rename(user_id, name)` (or reset it with a null name).
